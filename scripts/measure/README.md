# 토큰 측정 스크립트

`review/code-mode-review.md` 의 숫자를 다시 내는 스크립트다. 클로드 코드 세션 로그(`~/.claude/projects/**/*.jsonl`)에서 TalkToFigma 를 부른 본 세션만 골라 읽는다. 서브에이전트 로그는 뺀다.

## 실행 (저장소 루트에서)

```bash
bun run build                          # dist/server.cjs 가 있어야 한다
cd scripts/measure
# 결과 폴더: 기본 ~/.cache/talk-to-figma-measure (0700, 파일 0600). 바꾸려면 MEASURE_OUT=<본인 소유 폴더>
node list.mjs ../../dist/server.cjs    # 도구 정의 96개 → tools.json
node extract.mjs                       # 세션 타임라인 → events.json
node calib.mjs                         # 토큰/글자 계수(usage 기반 회귀)
node compose.mjs                       # Messages 구성, 명령별 결과 토큰, 파일로 빠진 결과
node fields.mjs                        # 다음 턴에 쓴 필드 → fields.json
node sim.mjs                           # Code Mode 접기·거르기, fields 옵션, 세션 나누기
node breakdown.mjs                     # Messages 항목별 내역, 파일 다시 읽기, 세션 나누기 순감소
node segs.mjs && node rep.mjs          # 대표 구간 후보와 비교
node sessions.mjs --since YYYY-MM-DD   # 세션 나누기 시범 측정 (아래)
```

## 시범 측정: 작업이 바뀔 때마다 새 세션 열기

문서 §3.2 의 세션 나누기 순감소(5~25%)는 추정이다. 실제 세션으로 확인하는 절차는 다음과 같다.

1. 시작 날짜를 정한다(예: 2026-11-28). 그날부터 **5개 세션**은 작업이 바뀔 때마다 새 세션을 연다.
   - 이전 작업에서 이어 갈 내용은 첫 메시지에 짧게 요약해 붙인다.
   - 시범 기간에는 기존 세션을 다른 작업에 이어 쓰지 않는다. 같은 날 시작한 다른 세션도 시범으로 잡히기 때문이다.
2. 5개 세션이 끝나면 위 실행 순서대로 `list.mjs`, `extract.mjs` 를 다시 돌려 events.json 을 새로 만든다.
3. `node sessions.mjs --since 2026-11-28` 을 돌린다. 그 날짜 이후 시작한 세션은 "시범", 이전 세션은 "기준"으로 나눠 아래 숫자를 낸다. 모두 로그 usage 로 잰 [측정] 값이다.

| 숫자 | 뜻 | 기준값 (지난 20세션, 2026-11-02 ~ 11-23) |
|---|---|---|
| 세션당 R | 호출마다의 Messages 크기 합 = 다시 읽는 Messages 합계 | 평균 36.52M · 중앙값 12.36M |
| 호출당 R | 세션 길이 차이를 뺀 비교값 | 중앙값 102.6K |
| 첫 턴 문맥 | 시스템 프롬프트·도구·CLAUDE.md + 첫 메시지(넘겨받기 요약 포함) | 중앙값 50.2K |
| 첫 피그마 호출 전 토큰 | 첫 턴 뒤 첫 피그마 호출까지 붙은 토큰(요약 다시 읽기, 파일 다시 읽기, 도구 불러오기) = 넘겨받기에 쓴 토큰 | 중앙값 22.3K |
| 압축 횟수 | 세션당 대화 압축이 일어난 횟수 | 세션당 0.50회 |

읽는 법
- **넘겨받기 비용** = (시범 첫 턴 문맥 − 기준 첫 턴 문맥) + 시범 첫 피그마 전 토큰. 문서의 가정(구간당 10K~30K)과 비교한다.
- **효과** = 호출당 R 중앙값이 기준보다 얼마나 줄었는지. 문서의 순감소(200자 경계 −14~25%, 500자 경계 −5~8%) 중 어느 쪽에 가까운지 본다.
- 5세션은 표본이 작다. 중앙값으로 비교하고, 세션마다의 줄(맨 위 표)도 같이 본다.

## 주의

- `sim.mjs` 와 `breakdown.mjs` 는 첫 인자로 가정값을 JSON 으로 받는다. 예: `node breakdown.mjs '{"minLen":500,"summary":5000,"writeX":38.5}'` (writeX = 캐시 쓰기 1토큰을 읽기 몇 토큰으로 칠지, 기본 38.5)
- 숫자가 문서와 다르면 로그가 늘어났기 때문이다. 세션이 추가되면 결과도 바뀐다.
- `breakdown.mjs` 의 R 총량(730.4M)은 문서 작성 당시의 값을 코드에 적어 둔 것이다. 로그가 바뀌면 `sim.mjs` 출력값으로 고친다.
- `rep.mjs` 는 문서에 쓴 구간을 세션 id 앞부분과 호출 순번으로 고른다.
- 결과 폴더에는 로그 원문이 들어 있다. 커밋하지 말고, 공유 `/tmp` 처럼 남이 쓸 수 있는 곳에 두지 않는다. 심볼릭 링크이거나 다른 사용자 소유인 폴더면 스크립트가 멈춘다.
- `extract.mjs` 는 TalkToFigma 를 한 번이라도 부른 세션만 고른다. 시범 세션에서 피그마를 안 쓴 세션은 비교에 들어가지 않는다.
